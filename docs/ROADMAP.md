## 架构原则：服务器是边缘性的

BZ-Games 是**本地优先**的 Windows 游戏平台。官方 Relay Server 仅提供三项边缘能力，任何主要功能都不依赖服务器：

| 能力         | 说明                               | 离线时的影响                       |
| :----------- | :--------------------------------- | :--------------------------------- |
| 房间中继     | 帮助无法直连的玩家通过公网中转联机 | LAN / frp 直连完全不受影响         |
| GitHub OAuth | 云端同步功能的身份认证入口         | 所有本地功能无需登录               |
| 云端文件同步 | config + SQLite 数据的远程备份     | 不影响本地使用，数据始终以本地为准 |

## v3.2 — Polish（打磨）

### 目标

修复边缘场景 Bug，打磨交互细节，提升大型游戏库下的流畅度。

### 计划特性

**性能优化**

- 游戏封面图片懒加载，降低首屏渲染压力
- 大型库搜索增加防抖
- 批量导入时减少不必要的重渲染

**游戏库体验**

- Steam 模式列表支持 Shift/Ctrl 多选批量操作（删除、移动存储路径）
- 已安装版本快速切换入口
- 右键菜单增加「打开游戏目录」

**市场体验**

- 版本更新日志（Release Notes）在详情页展示
- 下载队列并行数可配置
- 安装完成后自动清理缓存归档文件

**联机体验**

- 房间内显示各玩家延迟
- 聊天消息支持 Markdown 基础语法
- 加入房间失败时给出明确错误原因

**数据库**

- 健康检查自动清理孤立数据（版本目录已被物理删除的 GameRecord 条目）

## v3.5 — Social（社交）

### 目标

构建立足于本地的社交系统。LAN 内自动发现，跨网络好友通过 Relay Server 通信，**前提是双方均已 GitHub 登录**（以此作为全局唯一身份标识）。

### 计划特性

**好友系统**

- 好友列表存于本地 config，含玩家 ID、昵称、备注
- **LAN 发现**：基于现有 `LocalNetworkService`（UDP 广播）自动发现局域网内好友，实时显示在线状态
- **Relay 跨网络**：双方 GitHub 登录后，通过 Relay Server 以 GitHub 用户名互加好友，实现跨网络在线状态同步和文字消息
- 好友间快捷邀请加入房间（LAN 或 Relay 通道，与联机三入口对齐）
- 离线消息缓存：Relay 好友发消息时若对方离线，消息暂存 Relay，上线后拉取

**好友间游戏分享**

- LAN 好友：TCP 直连传输游戏安装包，SHA256 自动校验，完成后自动导入
- Relay 好友：走 Relay 中继通道传输，受限于 Relay 带宽，适合小体积游戏

**截图管理**

- 全局快捷键截图（默认 `Ctrl+Shift+S`）
- 按游戏 ID 自动分组存储
- 内置截图浏览器：预览、删除、复制、打开文件夹
- 成就解锁时自动截图（可配置开关）

## v4.0 — Create（创作生态）

### 目标

从消费平台扩展为创作与分发平台。创作工具本地运行，分发可通过 GitHub 或服务器托管两条路径。

### 计划特性

**MOD 系统**

- 游戏在 `game.json` 中声明 `modSupport: true`
- MOD 格式：`.bzmod` 包，含覆盖文件和 `mod.json`
- 本地 MOD 管理面板：启用/禁用/排序，冲突检测
- 游戏启动时按优先级叠加 MOD 文件

**游戏存档管理器**

- 统一的存档浏览与备份界面
- 自动检测各游戏存档目录（基于 game.json 声明）
- 本地版本化备份，支持导出/导入

**开发者工具**

- 内置 game.json 编辑器（可视化表单 + JSON 预览）
- Game API 调试面板（发送/接收消息、查看日志）
- 一键打包为标准游戏安装包

**市场扩展**

- 社区创作者通过 GitHub PR 提交游戏到第三方市场源
- 自动化 CI 校验（格式检查、SHA256 验证）
- 审核通过后自动更新市场索引

**服务器托管发布**

- 开发者在平台内一键将游戏包上传至 Relay Server（需 GitHub 登录）
- 服务器自动校验 game.json 格式与 SHA256，生成版本条目
- 提供开发者面板：管理已发布游戏、查看下载量、更新/下架版本
- 用户从市场安装时，从服务器 CDN 直接下载，无需 GitHub Release
- 降低非技术开发者的发布门槛，无需操作 Git 仓库和 Release 流程

## 设计原则

1. **本地优先**：核心体验不依赖服务器，云端功能始终是可选增强
2. **向后兼容**：新版本不破坏旧版游戏包和 Game API
3. **用户数据主权**：数据始终存储在本地，云端同步需用户主动授权
4. **轻量高内聚**：控制安装包体积，避免引入臃肿框架
5. **开放标准**：游戏包格式、Game API 协议均文档化并开放
