## 当前平台能力总览

BZ-Games 已完成从 v1.x 到 v3.0 的核心迭代，当前具备以下能力：

| 模块 | 现状 |
|:---|:---|
| **游戏库** | 本地导入、版本管理、收藏、拖拽排序、删除特效、草稿导入、Web/Exe/Bat 多入口 |
| **游戏市场** | 官方市场 + 第三方市场 + GitHub Release 市场，主备双源，下载队列、浮球进度、断点续传 |
| **联机房间** | 创建/加入/准备/聊天/踢人/断线重连/房间密码，LAN 发现 + frp 直连 + Relay 中继三入口 |
| **Game API** | v1 JSON + v2 二进制帧，消息发送/广播/订阅，环境变量/BZ_CONFIG 注入，成就解锁、统计数据上报 |
| **成就系统** | 游戏定义成就列表，平台追踪解锁状态，弹窗通知，成就面板 |
| **统计系统** | 游玩时长、日历热力图、会话记录，better-sqlite3 持久化 |
| **经济系统** | BZ 币、每日签到（连续/累计）、游玩时长奖励、签到 7 天额外奖励 |
| **个性化** | 头像上传裁剪、头像框（游玩/签到/购买解锁）、昵称样式（渐变色/发光/粒子特效等 9 种） |
| **云端同步** | GitHub OAuth 登录，config.json + play_sessions.db 云备份，MySQL + MongoDB GridFS |
| **Relay Server** | 房间中继、短地址、OAuth、云文件同步，独立 Node.js 服务 |
| **国际化** | 简体中文 / English / 日本語 / 繁體中文 / 文言文 / Deutsch 六语言 |
| **聊天** | 支持文字、语音消息（最长10秒）、图片（拖拽/粘贴），弹出独立聊天窗口 |
| **体验** | 自动更新、托盘最小化、暗色/亮色/自动主题、战绩报告卡 |
| **兼容** | 支持 .zip / .7z 解压，extract-zip + 7za 双引擎，sha256 + size 双重校验 |

## 版本策略

BZ-Games 采用 **渐进式版本演进** 策略，每个大版本聚焦一个核心主题：

| 版本 | 代号 | 主题 | 预计跨度 |
|:---|:---|:---|:---|
| **v3.1** | *Refine* | 体验打磨 | 1-2 个月 |
| **v3.2** | *Social* | 社交与分享 | 2-3 个月 |
| **v3.5** | *Cross* | 跨平台与移动 | 3-5 个月 |
| **v4.0** | *Studio* | 创作者生态 | 4-6 个月 |

## v3.1 — Refine（体验打磨）

### 目标

在 v3.0 的稳定架构之上，打磨细节体验，提升性能与可靠性，为后续功能打好地基。

### 3.1.0 核心特性

#### 1. 游戏存档云备份

**现状**：游戏存档完全本地存储，用户更换设备或重装系统后面临存档丢失风险。

**方案**：
- 设置页新增「云备份」面板
- 利用已有的 GitHub OAuth + Relay Server 基础设施，存档上传到云端
- 手动备份 / 游戏退出时自动备份
- 按游戏 + 版本自动扫描存档目录，打包上传
- 还原时版本匹配检查

**可行性**：`CloudSyncService` 已实现 config.json 和 play_sessions.db 的云端同步，可扩展支持游戏存档目录。`StoreService` 管理游戏文件路径。

#### 2. 性能优化 — 大型游戏库

**现状**：游戏库超过 100 个游戏时，`LibraryView` 加载可能出现卡顿。

**方案**：
- 游戏封面图片懒加载（基于现有 `CachedImg` 组件增强）
- `loadGames()` 增量加载
- 大型游戏库搜索增加防抖
- 库视图虚拟滚动

**可行性**：Vue 3 响应式系统天然支持细粒度更新，仅需在组件层面增加虚拟滚动和懒加载逻辑。

#### 3. 手柄支持增强

**现状**：平台本身不做手柄映射，完全依赖游戏自行处理。

**方案**：
- 新增全局手柄配置页：按键映射、振动强度、死区设置
- 通过 HTML5 Gamepad API 在 Web 游戏中提供统一手柄输入
- 为 Native 游戏提供可选的手柄输入桥接

**可行性**：Electron 支持 Gamepad API，主进程可通过 native addon 实现手柄输入转发。

#### 4. 市场详情页增强

**现状**：市场游戏详情已展示基础信息、版本列表、封面和下载进度。

**方案**：
- 版本更新日志（Release Notes）Markdown 渲染展示
- 「相关游戏」推荐（基于标签/分类）
- 下载队列并行数可配置

**可行性**：`MarketGameVersionSchema` 已有 `releaseNotes` 字段，仅需 UI 层面增强。

## v3.2 — Social（社交与分享）

### 目标

从单机 + 点对点联机，扩展为具备轻社交属性的游戏平台。

### 3.2.0 核心特性

#### 1. 好友系统

**方案**：
- 基于玩家 ID 的好友添加 / 删除
- 好友在线状态（通过 Relay Server 订阅）
- 好友列表 UI：头像框、当前游戏、快捷邀请
- 好友间私聊（走 Relay 中继）

**架构影响**：
- `StoreService` 新增 `friends` 存储字段
- `relay-server` 新增好友状态订阅/推送 channel
- 渲染进程新增 `FriendsView`

**可行性**：Relay Server 已有 WebSocket 基础设施，新增好友状态 channel 只需扩展消息类型。

#### 2. LAN 游戏分享

**方案**：
- 同一局域网内的 BZ-Games 实例可互相发现
- 支持「一键发送游戏到好友」— LAN P2P 传输游戏文件
- 接收方自动校验 SHA256
- 传输进度在通知中心展示

**可行性**：已有 `LocalNetworkService`（UDP 广播发现），可复用其发现机制。

#### 3. 游戏截图与录制

**方案**：
- 全局快捷键截图（默认 `Ctrl+Shift+S`），自动保存到截图库
- 支持录制最近 N 秒的回放剪辑（类似 NVIDIA ShadowPlay）
- 截图管理面板：按游戏分组、标签
- 游戏中成就解锁时自动截图

**可行性**：Electron 的 `desktopCapturer` + `BrowserWindow.capturePage()` 可实现截图。回放录制可用 `MediaRecorder` API + 循环缓冲区。

#### 4. 活动 Feed

**方案**：
- 首页新增动态 Feed 面板（可折叠）
  - 好友解锁了新成就
  - 市场有游戏更新
  - 自己获得的成就回顾（「1年前的今天你解锁了...」）
- 动态数据存储于本地 + relay 转发

**可行性**：成就弹窗体系已完善，扩展为 Feed 条目即可。

## v3.5 — Cross（跨平台与移动）

### 目标

打破 Windows 桌面端边界，让 BZ-Games 成为跨平台的游戏平台。

### 3.5.0 核心特性

#### 1. macOS 与 Linux 支持

**方案**：
- 主进程服务抽象化：平台相关代码用策略模式分离
- macOS：.app 打包、DMG 分发
- Linux：AppImage / Flatpak / deb 打包
- 7z 解压使用各平台对应二进制
- 窗口管理适配各平台托盘、菜单、快捷键规范

**可行性**：Electron 本身就是跨平台框架，当前限制主要是 `better-sqlite3`（支持三平台）、7z 路径硬编码和 NSIS 安装器。

#### 2. 移动端伴侣 App

**方案**：
- 轻量移动端 App（React Native），不作为完整游戏平台
- 核心功能：
  - 查看游戏库、成就、统计
  - 接收好友邀请通知
  - 远程管理下载队列
  - 聊天消息推送
- 通过 Relay Server 与桌面端通信

**可行性**：Relay Server 作为通信桥梁已就绪。移动端本质上是 Relay Server 的另一个 WebSocket 客户端。

#### 3. Web 版游戏启动器

**方案**：
- 纯 Web 版 BZ-Games（运行在浏览器中）
- 仅支持 `networkgame` 类型游戏（直接 URL 启动）
- 不支持本地游戏导入和联机房间（浏览器限制）
- 作为「轻量入口」，降低新用户门槛

**可行性**：App 路由系统已是标准 Vue 3 SPA，独立构建部署即可。

## v4.0 — Studio（创作者生态）

### 目标

从游戏消费平台升级为游戏创作与分发平台。

### 4.0.0 核心特性

#### 1. 可视化游戏编辑器

**方案**：
- 内置轻量级 2D 游戏编辑器（基于 Phaser 或 PixiJS）
  - 场景编辑器（拖拽精灵、碰撞体）
  - 事件系统编辑器
- 一键导出为标准 BZ-Games 格式（符合 `game.json` 规范）
- 内置 Game API 调试面板

**可行性**：平台已有完整的游戏包规范和 Game API，编辑器主要解决「生成合规游戏包」的问题。

#### 2. 创作者工坊

**方案**：
- 用户可上传自制游戏到创作者工坊
- 工坊游戏支持评分、评论、收藏
- 工坊审核机制：自动扫描 + 社区举报
- 游戏可通过工坊直接安装到本地游戏库

**可行性**：市场系统已有完整的游戏元数据 Schema 和下载/安装流程。工坊是「用户投稿的市场」，架构可高度复用。

#### 3. MOD 系统

**方案**：
- 游戏可声明 `mod_support: true`
- MOD 格式：`.bzmod` 归档包，包含覆盖文件和 `mod.json` 清单
- MOD 管理面板：启用/禁用/排序
- MOD 工坊（复用创作者工坊基础设施）

**可行性**：`GameEnvironment` 负责游戏文件管理，MOD 加载本质是文件覆盖层。

## 长期愿景（v4.x+）

| 方向 | 简述 |
|:---|:---|
| **AI 游戏助手** | 本地 LLM 集成（Ollama），游戏攻略 RAG 问答、AI 游戏伙伴 |
| **去中心化 P2P** | 基于 libp2p 的 DHT 房间发现，不再依赖中心化 Relay Server |
| **游戏云串流** | 基于 WebRTC 的低延迟串流，朋友无需安装即可远程试玩 |
| **VR / AR 支持** | WebXR 游戏类型，VR 虚拟大厅浏览游戏库 |
| **游戏保存计划** | 老游戏/Flash 归档与兼容层（DOSBox、Ruffle） |
| **无障碍** | 屏幕阅读器支持、色盲模式、单手操作模式 |

## 架构演进原则

所有版本规划遵循以下核心原则：

1. **渐进增强，不破坏**：新版本必须向后兼容旧版本游戏包和 API
2. **本地优先**：核心体验不依赖云端服务，离线可用
3. **用户数据主权**：用户数据始终存储在本地，云端功能为可选增强
4. **轻量高内聚**：避免依赖臃肿，保持安装包 < 200MB
5. **开放标准**：游戏包格式、Game API 协议、存档格式均文档化并开放
