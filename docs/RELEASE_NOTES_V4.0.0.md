# BZ-Games v4.0.0 更新日志

v4.0.0 是安装、更新和本地数据模型的全面升级版本。

v4.0.0 发布前的实验协议和入口均不构成正式契约，正式版本不包含相应兜底、别名或运行时迁移分支；v3.4.2 V1 数据导入是 v4 的长期正式能力，而不是运行时兼容设计。

- 改用 Velopack 1.2.0 管理全量与增量更新，并增加 Rust 根启动器、安装向导、健康守护和自动回滚。
- 更新后的目标版本连续两次未通过健康启动时，根启动器会自动回退到更新前版本，并恢复更新前配置和数据库；游戏文件保持不变。客户端不提供手动回退入口。
- 后续常规 Windows 构建会自动下载上一稳定版 full/feed 并生成 delta；4.0.0 首发只提供 full。
- 更新回退只采用一套 4.x 协议：下载前保存当前版本 full 包，应用前从该唯一来源生成自动回退点；不兼容实验版回退状态，也不复用或猜测其他包来源。
- 程序运行区固定在 `.runtime/`；`config.json`、`games/`、`db/` 永久位于更新区外。
- 更新只在健康启动 30 秒后检查一次，不再周期检查；“稍后再说”可抑制当前安装版本的全部自动提醒，手动检查始终可用。
- 配置升级为严格 AES-256-GCM v4 信封；SQLite 使用唯一最终 Schema、`user_version=40000`、结构指纹与完整性校验。
- 游戏库迁入 `game_libraries`，游戏版本改为 `library_id + relative_path + lifecycle_state`，不再保存旧绝对路径和 `is_present`。
- 游戏库迁移以稳定 `library_id` 为事务边界：空目标校验、复制校验、数据库根路径提交和源目录删除均支持有限重试，失败时恢复原根路径及文件状态。
- 清除缓存只作用于当前 Electron 身份的 HTTP/市场缓存；删除旧 `.update-snapshots` 启动恢复、旧应用缓存路径、同步导入别名和废弃 IPC。
- 新增 Game Manifest V2 国际化协议，游戏库、详情、成就、统计、通知和启动语言注入统一消费本地化投影；Manifest V1 继续长期支持。
- 游戏市场升级为严格 Schema 2，游戏名、简介、标签和版本文案支持五种语言，并以稳定 `marketId` 贯穿路由、IPC、安装任务和论坛指令标签。
- 市场版本声明 `gameManifest` 时不再合并包内配置，而是在安装暂存区删除原 `game.json` 后从零生成对应 V1/V2 Manifest，再校验、加密并导入。
- 新增 `.bzgames` V2 长期备份与完整替换导入；永久支持 v3.4.2 V1 迁移包导入。
- V1 导入会在隔离转换器中创建全新 v4 数据：转换路径和字段、丢弃旧配置历史、只读取 `db/bz_games.db`，并加密所有旧明文 `game.json`。
- GitHub OAuth 仅用于社区身份、反馈、昵称同步与在线状态；V4 不提供平台云快照，客户端与服务端均不保留上传、下载或快照路由。
- V2 备份和 V1 导入不会导出或导入账号会话、账号身份及 GitHub Token。
- 建言献策历史继续使用服务端键集游标无限滚动，不再读取或清理本地旧历史字段。
- Windows 卸载改为安装根目录独立 `BZ-Games-Uninstall.exe`：系统入口固定保留游戏与用户数据，游戏内入口支持独立选择数据清理，并通过临时 worker 和阶段 journal 继续未完成操作。卸载采用单向提交，不为游戏或用户数据创建卸载备份、失败时不回退已完成阶段；根卸载器始终作为最后一个程序文件删除，失败后可再次运行继续卸载。

从 v3.4.2 迁移时，请先在旧版导出 `.bzgames`，安装 v4.0.0 后从设置页导入。确认新版本健康启动并验证数据后，再手动卸载旧客户端；导入和卸载都不会自动删除源备份。
